# 契约施工法 · 文档模板

五份模板,按 P0/P1/P2/P4 产出对号入座。所有 `<占位符>` 换成真实值;用不到的节整节删掉,别留空壳。

---

## 1. DESIGN.md(工程契约)模板

```markdown
# <项目> 工程契约 DESIGN.md

> 本文是契约:这里的值就是代码里的值。代码与本文不一致时,同一次提交修掉其中一个。
> 改实现先改本文。演进只加「取代条款」(vN 条款取代下文不一致处),不重写历史。

## §1 原则(5–8 条,每条一句话 + 为什么)
1. **<原则名>。** <要求>——<为什么>。
2. ...

## §2 接口契约
| 名称 | 形状 | 语义 | 变更纪律 |
|---|---|---|---|
| `GET /api/<x>` | `{字段:类型}` | <语义> | 只加字段不删改 |
| `<模块>.<函数>` | 签名 | <语义> | ...

## §3 数据契约
- 存储:<位置/格式>;唯一真相在 <哪>;派生物在 <哪>,如何重算
- 兼容:Schema 版本号 <N>,升级走迁移 <方式>,禁止静默改历史数据

## §4 错误与降级
- 外部依赖失败 → <降级行为>(明确"显示什么"而不是"报错")
- 解析器自检:<输出合理性判据,如"条目数 <N 即判定损坏">,坏了降级不吐垃圾

## §5 Do Not(禁止清单)
- <明令禁止的做法 1>
- <明令禁止的做法 2>

## §6 测试纪律
- 每个契约条款至少一项测试锚定;fixture 录制回放,敏感字段脱敏后可提交
- 验证命令:<怎么跑全部验证>
```

## 4. review-<date>.md(独立审查产出)模板

> 审查代理的任务书要点:只给契约文档 + 代码,不给施工对话;
> 按契约逐条对账;读不懂的条款单独列出(那是契约的问题,不是代码的)。

```markdown
# Review <date>

按 <DESIGN/VISUAL.md> 条款对账。三类分栏,逐条编号。

## 契约违背
- [R1] §<条款号>:<代码哪里违背了什么> → <建议>

## 缺陷
- [B1] <不依赖契约也成立的问题> → <建议>

## 未验证项
- [V1] <审查者无法在静态审查中确认的事>

## 契议(契约写得虚的条款)
- [C1] §<条款号> 读不懂/无法对账:<原因> → <怎么改条款>
```

## 5. IMPLEMENTATION-<date>.md(实施回执)模板

> 判决行/逐条核验/修复轮计数融合自 NEXUS QA 回执(agency-agents,MIT;
> 快照存 `references/nexus-handoff-templates.md`)。

```markdown
# 实施回执 <date>

本轮按 `review-<date>.md` 的审查意见实现,<保留/调整> 了 <架构要点>。

## 判决:PASS / NEEDS WORK
波次 <N>;修复轮 <M>/3;日期 <YYYY-MM-DD>。

## 验收核验(对 P0 验收清单逐条)
- [x] <P0 验收条 1> — 验证方式:`<命令/截图路径>`
- [x] <P0 验收条 2> — 验证方式:...
- [ ] <P0 验收条 3> — 未达成/未覆盖(对应下方待办或诚实边界)

## 验证证据
- `<验证命令>`:通过。<测试数分模块,如 schema 20 / pipeline 314 / web 507,共 975 项>
- 静态检查:<lint/tsc 结果>;构建:<结果>
- 手测:<视口/页面/检查项,如"桌面+390px:无横向溢出,无控制台报错">;截图:<路径,双视口每页一张>

## 修复内容
- **<类别,如 故障修复>**
  - <修了什么,一行一条,尾注 review 编号如 (R1/B3)>
- **<类别,如 阅读与界面>**
  - ...

## 诚实边界(本轮未验证)
- <未测的部分,如"真实投递未测,仅本地 mock""动画验证了行为,未做帧率基准">

<关联:下一步谁来做、凭据依赖等>
```

**判决纪律**:
- PASS 的唯一标准:P0 验收清单全 [x] 且每条有证据。差一条就是 NEEDS WORK,写明差在哪。
- NEEDS WORK 不是失败,是"尚未过闸":差异项要么当波修掉重判,要么转显式待办,
  由用户决定是否降级验收。
- 修复轮 M≥3 仍 NEEDS WORK:停止硬修,升级用户决策(对应 P3「不带病交付」)。

## 6. 子代理任务书(交接文档)模板

> P1 第③步派单用。融合自 NEXUS Standard Handoff——纸面交接防上下文丢失。
> 核心纪律不变:**只给契约路径与目标,不给施工对话**。

```markdown
# 任务书:<一句话目标>

| 项 | 值 |
|---|---|
| 契约 | `docs/<DESIGN|VISUAL>.md`(对 §<条款范围> 负责) |
| 波次 | <N>;日期 <YYYY-MM-DD> |

## 当前状态
<已完成什么,一句话;依赖什么,一行>

## 相关文件
- `<路径>` — <是什么/改哪里>
- `<路径>` — ...

## 验收标准(抄 P0 对应条目)
- [ ] <条 1>
- [ ] <条 2>

## 完成证明(回报什么)
- 测试:`<命令>`,回报分模块数
- 截图:<哪些页×双视口,存哪>
- 未验证项:<如实列,进回执「诚实边界」>
```

**闭环**:P0 验收标准 → 任务书复选框 → 子代理完成证明 → P4 回执逐条核验——同一份清单走全程,
每道环节对同一批条目负责。
